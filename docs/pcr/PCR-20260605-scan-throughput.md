# PCR-20260605-scan-throughput

## 1. 基本信息

- PCR 编号：PCR-20260605-scan-throughput
- 提出日期：2026-06-05
- 提出人：现场试运行反馈
- 变更类型：功能体验 / 性能优化
- 影响模块：检验扫描、扫描接口、今日检验明细
- 当前状态：已实现，待现场更新验证

## 2. 变更背景

现场连续扫码时，系统响应跟不上。经代码排查，检验扫描页面在每提交一条记录后都会重新拉取当天当前产线的全部检验明细，并且条码输入框在解析、提交、刷新期间会被禁用。当天记录越多，提交后的等待越长；扫码枪连续输入时，后续条码存在被禁用输入框吞掉的风险。

## 3. 变更范围

- 正常合格扫码改为队列式顺序处理。
- 正常扫码时条码输入框保持可输入，Enter 后立即入队并清空输入框。
- 检验提交成功后，使用接口返回的新记录直接追加到今日明细顶部，不再每条记录提交后重新拉取全量今日明细。
- 今日检验明细接口限制为最新 80 条记录。
- 增加前端队列处理测试和后端最新 80 条限制测试。

## 4. 不在范围

- 不调整外部水洗唛接口协议。
- 不修改数据库表结构或迁移。
- 不改变合格、重复合格、不合格、条码污损等业务规则。
- 不新增查询分析分页或筛选逻辑；完整历史查询仍通过查询分析模块处理。

## 5. 实施内容

- 检验扫描页增加连续扫码队列，后台按顺序解析和提交正常合格扫码。
- 队列处理期间显示当前处理条码和待处理数量。
- 若某条扫码解析或提交失败，系统暂停连续扫码队列并提示异常，避免错误被后续自动提交覆盖。
- 提交成功后将创建结果插入今日明细列表，并保留最近 80 条。
- 后端 `/scanning/today-records` 查询增加 `take: 80`，继续按 `scannedAt desc` 返回最新记录。
- 更新相关自动化测试，覆盖连续扫码入队和明细接口限制。

## 6. 数据库与数据影响

- 不涉及数据库结构变更。

- 历史检验记录保留不变。
- 扫码页仅显示最近 80 条今日记录，完整明细仍在查询分析中查看。
