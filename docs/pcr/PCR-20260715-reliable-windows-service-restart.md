# PCR-20260715-reliable-windows-service-restart

## 1. 基本信息

- PCR 编号：PCR-20260715-02
- 提出日期：2026-07-15
- 提出人：现场用户
- 变更类型：部署与运维可靠性修复
- 影响模块：Windows 部署脚本、更新包说明、部署手册
- 当前状态：已实施，待随下一更新包发布

## 2. 变更背景

现场修改生产订单接口地址后，单独停止并启动 `ScanApi` 计划任务未结束其 Node 子进程。旧进程继续占用 3000 端口并使用旧环境配置，新进程无法接管，导致所有终端扫码失败并返回 `SCAN_LOOKUP_UNAVAILABLE`。

## 3. 变更范围

- Windows Install、Update、Restart 三种模式的服务重启行为。
- `ScanApi`、`ScanWeb` 计划任务及其项目 Node 子进程清理。
- 完整安装包和更新包内的 `README-WINDOWS.txt`。
- Windows 部署手册及自动化脚本检查。

## 4. 不在范围

- 不修改业务功能、接口协议和页面交互。
- 不修改数据库结构和历史业务数据。
- 不停止或调整独立运行的 `ScanDatabaseBackup` 任务。

## 5. 实施内容

新增统一的 `Restart-ScanServices` 流程：

1. 停止 `ScanApi` 和 `ScanWeb` 计划任务。
2. 强制结束属于本项目的残留 Node 进程。
3. 验证 3000、8080 端口均已释放；如仍被占用，输出 PID 和命令行并终止部署，不清理无关进程。
4. 同时重新启动 `ScanApi` 和 `ScanWeb`。
5. 在 30 秒内循环检查 API 和 Web；任一健康检查失败即终止部署，不输出部署成功。

Install、Update 和 Restart 均使用该规则。运维人员不得再将单独停止、启动某一个计划任务作为标准重启方式。

## 6. 数据库与数据影响

无数据库迁移，不修改或覆盖 `C:\scan\data\scan.db`。更新模式仍按既有规则在部署前备份数据库。

## 7. 权限与审计影响

部署脚本继续由 Windows 管理员执行，计划任务继续以 `SYSTEM` 身份运行。不改变应用权限和业务审计日志。

## 8. 验证结果

- 自动化测试验证统一重启函数包含双任务停止、残留进程清理和双任务启动。
- 自动化测试验证 Restart 模式及部署完成阶段均调用统一重启函数。
- 自动化测试验证端口未释放和健康检查超时都会抛出错误。
- 自动化测试验证完整包、更新包和部署手册均说明该规则。

## 9. 部署注意事项

人工重启必须执行：

```powershell
cd C:\scan\Scan
.\scripts\deploy-windows.ps1 -Mode Restart -ServerIp "192.168.1.144"
```

该操作会同时短暂中断 API 和 Web 服务，数据库文件不受影响。

## 10. 回滚方案

恢复上一版 `scripts\deploy-windows.ps1`。如出现任务启动异常，可先结束占用 3000、8080 端口的本项目 Node 进程，再手工启动 `ScanApi` 和 `ScanWeb`；无需数据库回滚。
