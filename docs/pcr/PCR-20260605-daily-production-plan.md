# PCR-20260605-daily-production-plan

## 1. 基本信息

- PCR 编号：PCR-20260605-daily-production-plan
- 提出日期：2026-06-05
- 提出人：现场试运行反馈 / 项目负责人确认
- 变更类型：功能变更、数据模型变更、权限与审计变更
- 影响模块：生产计划、检验扫描、查询分析、操作日志、生产订单接口解析
- 当前状态：已实现，已本地验证

## 2. 变更背景

现场需要在每日生产开始前按生产订单下达日计划，并在检验扫描时监督订单完成情况。系统原有扫码记录只能统计检验结果，无法按生产订单判断当天是否已下达计划、计划是否完成，也无法在查询分析中查看订单维度的完成状态。

本次待确认项均已按“是”处理：

- 支持跨日复制昨日或指定日期计划。
- 支持关闭计划。
- 查询用户可下达和维护计划。
- 扫码拦截写入操作日志。

## 3. 变更范围

- 新增生产计划管理页面，供查询用户和管理员使用。
- 新增生产订单条码查询、日计划创建、调整、关闭、跨日复制和列表接口。
- 扫码提交增加生产订单号和日计划绑定。
- 普通水洗条码扫码时校验当天有效日计划。
- 查询分析新增订单完成视图。
- 生产订单接口解析新增生产订单号、订单数量和原始返回数据缓存。
- 新增数据库迁移和后端/前端测试覆盖。

## 4. 不在范围

- 不变更已有登录、主数据、缺陷原因和产线基础规则。
- 不清理或改写现场已有检验记录。
- 不新增班次维度计划。
- 不新增多级审批流。
- 不改变特殊条码规则；污损条码和无条码产品仍按原特殊条码逻辑处理。

## 5. 实施内容

- 数据库新增 `DailyProductionPlan`、`ProductionOrderCache`，并给 `InspectionRecord` 增加 `productionOrderNo`、`dailyProductionPlanId` 字段。
- 后端新增 `ProductionPlansModule`，提供生产计划查询、下达、调整、关闭、复制接口。
- 后端扫码服务在普通扫码提交时查找当天生产计划，并在无计划、已关闭或合格数达到计划数时拦截。
- 扫码拦截写入 `OperationLog`，动作包括未带生产订单号、无日计划、计划已完成。
- 前端新增“生产计划”导航模块，查询用户和管理员可见。
- 前端扫码页展示生产订单号和日计划完成状态，并在提交时带上生产订单号。
- 查询分析新增“订单完成”标签页，展示订单计划数、合格数、不合格数、剩余数、完成率和产线。

## 6. 数据库与数据影响

本次涉及数据库结构迁移，但迁移为增量新增，不删除、不重建、不清空现有表。

- 现场已有 `InspectionRecord` 数据保留。
- 既有检验记录新增字段默认为空：`productionOrderNo = NULL`、`dailyProductionPlanId = NULL`。
- 旧记录仍可在原有明细、看板和操作记录中查询。
- 订单完成统计只统计绑定到 `DailyProductionPlan` 的新记录；旧记录因没有生产订单和日计划绑定，不会被错误计入新订单完成口径。
- `ProductionOrderCache` 仅缓存生产订单接口返回值，便于计划下达和问题追溯。

## 7. 权限与审计影响

- 查询用户和管理员可以查询生产订单、下达日计划、调整计划数、关闭计划、跨日复制计划。
- 检验员不能进入生产计划管理接口。
- 计划创建、调整、关闭、复制写入 `OperationLog`。
- 扫码因日计划规则被拦截时写入 `OperationLog`，用于追溯现场异常。

## 9. 部署注意事项

- 现场更新前仍建议备份 `C:\scan\data\scan.db`。
- 更新时需要执行新增 Prisma/SQLite 迁移 `20260605093000_add_daily_production_plans`。
- 该迁移不删除现场数据，但上线后普通水洗条码扫码会要求存在当天有效生产计划。
- 上线前应确认生产订单接口返回字段中包含生产订单号和订单数量；当前实现支持常见别名字段。
- 现场首日使用前，需要由查询用户或管理员先下达当天计划，或从前一日复制计划后调整。

## 10. 回滚方案

- 如仅回滚代码且保留数据库新增字段/表，旧功能可继续读取原有检验记录。
- 如必须完全回滚数据库结构，应先停机并备份数据库，再按备份恢复；不建议在现场库上手工删除新增表或字段。
- 若生产计划规则影响现场扫码，可临时回退到上一版本部署包，并保留本次迁移后的数据库备份等待后续处理。
