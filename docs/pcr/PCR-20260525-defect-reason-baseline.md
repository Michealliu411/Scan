# PCR-20260525-defect-reason-baseline

## 1. 基本信息

- PCR 编号：PCR-20260525-defect-reason-baseline
- 提出日期：2026-05-25
- 提出人：试运行部署准备
- 变更类型：数据库基线数据变更
- 影响模块：基础数据、缺陷原因、不合格检验、Windows 部署包
- 当前状态：已实现，已完成随包数据库验证

## 2. 变更背景

现场重新安装时需要系统默认带出图片中确认的 42 条业务缺陷原因 A0-A41，避免安装后再由管理员逐条维护。

同时污损条码流程仍依赖系统缺陷原因 `BARCODE_DAMAGED / 条码污损`，因此随包数据库继续保留该系统项。

## 3. 变更范围

- Windows 随包基线数据库 `ScanData/scan.db`。
- 缺陷原因基础数据。

## 4. 不在范围

- 不改变用户、产线、操作工、特殊条码和业务检验记录。
- 不调整缺陷原因扣款金额，全部默认为 `0`。
- 不新增或修改缺陷原因维护页面功能。

## 5. 实施内容

在干净随包数据库中写入：

- 系统原因：`BARCODE_DAMAGED / 条码污损`。
- 业务原因：`A0` 到 `A41`，共 42 条，全部启用。

## 6. 数据库与数据影响

- `DefectReason` 表基线数据从 0 条调整为 43 条。
- 其中业务缺陷原因 42 条，系统污损条码原因 1 条。
- 其他表保持重新安装基线：仅 `admin` 用户和 `LINE-01 / 产线01` 默认产线，无业务检验记录、无操作记录、无会话。

## 7. 权限与审计影响

- 本次是安装包基线数据调整，不产生运行时操作审计记录。
- 安装后管理员仍可在基础数据中维护这些缺陷原因。

## 8. 验证结果

已验证随包数据库：

- `DefectReason` 总数：43。
- `A0-A41` 业务缺陷原因数量：42。
- `BARCODE_DAMAGED / 条码污损` 存在且启用。

## 9. 部署注意事项

- 仅在使用 `-FreshDatabase` 或全新安装时会直接采用随包基线数据。
- 如果保留旧数据库更新，旧库不会自动被这份基线覆盖，需要另行导入或手工维护缺陷原因。

## 10. 回滚方案

- 如果不需要这些缺陷原因，可在安装后由管理员停用或删除未被业务数据引用的原因。
- 不建议删除 `BARCODE_DAMAGED / 条码污损`，该项用于污损条码流程。
