# PCR-20260525-trial-run-hardening

## 1. 基本信息

- PCR 编号：PCR-20260525-trial-run-hardening
- 提出日期：2026-05-25
- 提出人：试运行反馈
- 变更类型：功能增强、缺陷修复、审计增强、数据库变更
- 影响模块：基础数据、查询分析、检验记录、特殊条码、操作记录、数据库迁移
- 当前状态：已实现，已完成本地验证

## 2. 变更背景

试运行后发现基础数据维护、查询分析和不合格原因维护仍有若干现场使用问题：

- 操作工列表需要按工号顺序查看。
- 基础数据新增入口需要改为弹窗，避免页面过长。
- 基础数据维护动作需要进入操作记录，形成审计。
- 合格品变更为不合格品、不合格原因修改也需要进入操作记录。
- 不合格品在明细查询中需要允许修改不合格原因。
- 不合格原因数量较多时，原因选择弹窗按钮位置不便操作。
- 基础数据列表需要按字段查询。
- 明细查询和操作记录需要分页，并限制单页最大数量。
- 污损条码依赖内置“条码污损”原因，该原因被删或停用后会导致新增失败。

## 3. 变更范围

- 基础数据：
  - 用户、缺陷原因、产线新增改为弹窗。
  - 用户、缺陷原因、操作工、产线、特殊条码列表增加本地查询。
  - 操作工列表按工号排序。
  - 基础数据新增、编辑、删除、重置密码写入通用操作记录。
- 查询分析：
  - 明细查询增加分页和每页数量。
  - 操作记录增加分页和每页数量。
  - 不合格记录允许修改缺陷原因。
  - 合格变不合格、修改不合格原因写入操作记录。
- 特殊条码：
  - 新增污损条码时，如果内置“条码污损”原因缺失、停用或被删除，保存时自动恢复。
- 数据库：
  - 新增通用操作记录表，用于审计基础数据和检验记录变更。

## 4. 不在范围

- 不新增 PDF 导出。
- 不调整当前 Excel 导出格式之外的报表需求。
- 不改变现有角色体系。
- 不改变基础数据删除保护的业务引用规则。
- 不要求基础数据列表在新增后自动重新查询，低频变更由用户自行刷新或切换触发刷新。

## 5. 实施内容

- 新增 `OperationLog` 数据模型和迁移脚本。
- 将基础数据维护动作写入 `OperationLog`，审计记录仅保存快照文本和标识，不对基础数据建立外键依赖。
- 将旧的合格变不合格记录同步迁移到通用操作记录查询口径。
- 新增不合格记录修改原因接口，并重新计算扣款金额。
- 前端查询分析新增明细分页、操作记录分页、原因修改入口和长列表弹窗布局。
- 前端基础数据新增本地查询框，按当前列表可见字段进行过滤。
- 前端用户、缺陷原因、产线新增表单改为弹窗。
- 污损条码保存逻辑增加内置缺陷原因自动恢复。
- 更新对应 API 和 Web 测试。
- 更新 `.planning/REQUIREMENTS.md` 和 `.planning/STATE.md`。

## 6. 数据库与数据影响

- 新增表：`OperationLog`。
- 新增迁移：`20260525090000_add_operation_logs`。
- 迁移会将既有 `InspectionRecordChangeLog` 数据复制进 `OperationLog`。
- `OperationLog` 不通过外键引用用户、缺陷原因、产线、操作工或特殊条码，因此不会阻止未被业务数据引用的基础数据删除。
- 污损条码保存时会确保 `BARCODE_DAMAGED / 条码污损` 缺陷原因存在且启用。

## 7. 权限与审计影响

- 基础数据新增、编辑、删除、重置密码进入操作记录。
- 合格变不合格进入操作记录。
- 不合格原因修改进入操作记录。
- 操作记录保存操作者账号快照，避免用户删除或停用后审计信息丢失。
- 已停用缺陷原因不再显示在后续可选原因列表中。

## 10. 回滚方案

- 代码回滚到本次变更前版本。
- 如果已执行迁移且需要完全回退，需要先备份现有数据库，再评估是否删除 `OperationLog` 表；一般建议保留审计表不影响业务运行。
